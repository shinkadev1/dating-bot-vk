# Правила работы

## Оркестрация Codex

Конфигурация: `.codex/config.toml`; роли: `.codex/agents/{explorer,planner,developer,reviewer,reporter}.toml`. Диспетчер и роли explorer/reporter — gpt-6-luna/low; developer — gpt-6.1-sol/medium; planner/reviewer — gpt-6-astra/high (выбрано пользователем вместо отсутствующего gpt-6.1-astra). Значения проверены по документации OpenAI и локальному каталогу моделей 31.10.2026.

Лимит `max_concurrent_threads_per_session = 4` относится к подагентам без основного потока; фактический runtime может ограничивать сильнее. Правила маршрутизации и подтверждения планов — в AGENTS.md. Read-only задаётся инструкциями ролей, а не отдельной песочницей. Текущий чат не переключает модель от изменения файла; настройки применяются при загрузке проекта и могут переопределяться настройками сессии. Project config требует доверенного проекта.

Источники: https://learn.chatgpt.com/docs/agent-configuration/subagents и https://developers.openai.com/api/docs/models .

## Перед изменением

- Прочитать `AGENTS.md`, [CURRENT_TASK.md](CURRENT_TASK.md), [STATE.md](STATE.md).
- Проверить `git status --short`, `git branch --show-current`, `git log -1 --oneline` из корня этого репозитория.
- Записать текущий запрос, границы и критерии готовности. Существующие изменения не откатывать и не включать автоматически в коммит.
- Искать через `rg`; читать только относящиеся к задаче модули и потребителей изменяемого контракта.

## Локальные правила

- DEV подменяет Chat API, но VK настоящий. Нужен тестовый токен: локальный Long Poll не должен конкурировать с production.
- Очередь не реализовывать здесь; UI и доставка — в этом репозитории, пары — в Chat API.
- При правках Worker читать `worker/README.md`; не считать локальное наличие Worker подтверждением его деплоя.

## Команды и проверка

Команды выполняются из корня репозитория, если не указано иначе. Это инструкция для будущих задач, не отчёт о пройденных проверках.

- Установить зависимости из `requirements.txt` в отдельном окружении.
- Для UI: `DEV_MODE=True` в локальном окружении, затем `python -m app.main`.
- Есть `docker-compose.dev.yml`; перед Compose проверить внешнюю сеть `CHAT_NETWORK`.
- Для Worker из `worker/`: `npm ci`, `npm run dev`, `npm run typecheck`.
- Проверять приветствие, кнопки, следующий диалог, остановку, жалобу, таймаут, медиа и доставку notice.

Не использовать production-деплой как способ проверки. Выполнять подходящие проверки и записывать точный результат и ограничения. Документальные изменения проверять по ссылкам, путям и diff; дополнительные обязательные проверки локального AGENTS учитывать отдельно.

## Секреты и состояние

Не сохранять значения .env/.dev.vars, токены, ключи, accounts.json, Telegram-сессии и реальные переписки в контексте или коммитах. Настройки описывать именами переменных и ссылками на примеры. Локальный код не подтверждает работоспособность внешнего сервиса.

## Поддержка памяти

- PROJECT — назначение и границы; ARCHITECTURE — структура и контракты; CONVENTIONS — правила и команды.
- CURRENT_TASK — текущий запрос, прогресс, проверки, блокеры и точный следующий шаг. Обновлять в начале, при существенном прогрессе и завершении.
- STATE — датированный снимок ветки/HEAD, исходные изменения, ограничения и подтверждённые результаты.
- CHANGELOG — важные завершённые изменения и причина; не переносить сюда планы и полные логи.
- При изменении межсервисных контрактов обновлять также общую память workspace, если доступна. Если другие репозитории недоступны, явно записать необходимую синхронизацию.
- Не затирать прогресс другой текущей работы. Факты, предположения и непроверенное различать явно.
